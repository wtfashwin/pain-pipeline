# Complaint to MVP Implementation Plan

Status: the reusable local pipeline and review fixes are complete. See [final QA](../../verification.md) for checks, regressions and the customer-demand/deployment limits. Repository publication was authorized separately after this plan; it does not establish a customer-app release.

> **For agentic workers:** Use bounded independent workers for contracts and persistence, then native integration and a fresh whole-project review. Steps are tracked below.

**Goal:** Deliver a runnable local four-stage complaint-to-MVP pipeline with honest stage gates and durable evidence.

**Architecture:** Strict TOON boundary contracts feed pure clustering/ranking. A verified append-only ledger supplies the state machine; CLI commands persist receipts and write new handoff artifacts without overwriting earlier files. Source collection and the acceptance runner are explicit bounded adapters.

**Tech Stack:** Node 24, TypeScript, @toon-format/toon 4.4.0, Node test runner.

**Spec:** docs/superpowers/specs/2026-10-22-pipeline-design.md

## Global Constraints

- No paid model or hosting calls, outreach, or customer-app deployment by this repository.
- Human selection and five distinct real users are required for a build-ready spec.
- All failures remain recorded; fixtures cannot become live evidence.
- TOON strict decoding, 2-space indent, exact schemas, completion marker and finish reason validation.
- Acceptance commands run as argv, never through a shell.

## Review Focus

- Valid-prefix truncation: reject missing completion marker and non-success finish reason.
- Reimported and syndicated records: deduplicate before counting mentions.
- Stale state: changed selection/spec must invalidate downstream runs.
- Mixed live/fixture records and duplicate user IDs must never unlock live build.
- Corrupt ledger, concurrent appends, command failures/timeouts must fail closed.
